# Task: HCI restructure + "juice" (all three physics practicals and the app shell)

Read `CLAUDE.md` first; all of its rules apply (`_Azm` naming and namespace, singleton rules,
three-layer separation, screen-space UI, documentation, never delete without asking, stop gates).

## Goal
Make the app feel right for a real Matric student on a budget Android phone: less reading, obvious
touch affordances, feedback for every action, help that escalates instead of blocking, and
results that are useful for the board practical exam (notebook table, viva). Add "juice" (motion,
sound, haptics) that makes the instruments feel physical **without ever leaking a measurement**.

## Who we design for (drives every decision below)
- 15–16 years old, English is a second language → short instructions, ≤ ~8 words per line.
- 6" budget phone, sometimes outdoors, shared → big targets, high contrast, low cost per frame.
- Short sessions, interruptions (calls) → a practical must survive leaving and coming back.
- Goal = pass the board practical + viva, fill the practical notebook → exam-shaped output.
- Never held a vernier or screw gauge → sound/haptics stand in for the physical feel.

## Decisions already taken by the user
- **No Urdu** for now.
- **Haptics:** CandyCoded HapticFeedback (`xyz.candycoded.hapticfeedback` v1.0.3, MIT, already in
  `Packages/manifest.json`). Wrapped by our own `Haptics_Azm` so it can be swapped.
- **Tweens:** **DOTween (free)**, installed by the user in `Assets/Plugins/Demigiant/DOTween`
  (UI module enabled). Called only through our `Motion_Azm` facade.
- Claude builds the UI through MCP; the user tests on a phone at each gate.
- **Auto-save/resume: approved** (local JSON in `Application.persistentDataPath`).
- **Perform-mode rubric:** Claude proposes one (flagged ASSUMPTION for the teacher).
- **Devices:** many different phones (and possibly tablets). **Target API 36** (set 2026-11-19;
  minimum stays API 25 so older phones still install). **Every layout must be anchored so it
  scales to any aspect ratio** — checked at 16:9, 20:9, 21:9 and 4:3 at every gate.
- **Interaction log (Stage 8): approved** ("nice to have"; local JSON only).
- **Notebook export plugin: BACKLOG** (students can take screenshots; not in this task).
- **BACKLOG: read the real apparatus** (not only the code-drawn magnifier): a "reading close-up"
  camera on the scale, crisp procedural tick marks (shader from the models' UV→mm mapping) + TMP
  numbers on the surface, matte scale strips, Show me highlighting on the 3D scale. Suggested split:
  Learn = magnifier + close-up, Perform = apparatus only (exam-like). Screw gauge harder (curved scale).
- **Device/haptics testing happens once, after the whole refactor** (no phone test per gate).
- **Stages are built in groups** with one combined gate per group: 1–3, then 4–6, then 7–8
  (no detail of any stage is skipped).

## Current state (survey 2026-11-19)
- All UI is generated by editor builders (`Scripts/Editor/*SceneBuilder_Azm.cs`); each builder
  rebuilds its whole scene. Two near-duplicate helper libraries (`UIBuilder_Azm`,
  `UIFactory_Azm`) and ~15 private helpers copied into every practical builder.
- `CylinderHUD_Azm` and `ScrewGaugeHUD_Azm` are near line-for-line copies; `PendulumHUD_Azm` is
  the older pattern and has no briefing, guide, sound or hints (its Stage 4 is still pending).
- `UITheme_Azm` has colour roles, one font, a corner radius and 12 code-drawn icons; **no type
  scale, spacing or motion tokens** (~25 different font sizes hard-coded in the builders).
- `UISound_Azm` = 4 procedural sine beeps, used by Cylinder/ScrewGauge only.
- All animation is hand-written coroutines/`Update` lerps (panels, toast, drawer, pill, table rows).
- One toast per scene, pinned top-left; hints are appended to it and can cover the apparatus.
- Settings: master/SFX volume, hints on/off, graphics Low/High, tutorial flags.

# STAGE 1 — Foundation: design tokens + feedback system
1. **Design tokens in `UITheme_Azm`:**
   - Type scale (5 steps, e.g. Display 56 / Title 40 / Body 32 / Label 28 / Caption 24 at the
     1920×1080 reference) with a **Large text** multiplier from Settings.
   - Spacing scale (8 / 16 / 24 / 32 / 48), touch size (≥ 120), radius, elevation (shadow) levels.
   - Motion tokens: durations (fast 0.12 / normal 0.25 / slow 0.45 s) and named eases.
   - Colour roles kept; add `Info`, and text/pattern pairs so no state is shown by colour alone.
2. **`Motion_Azm` (UI layer, static facade):** PopIn, PopOut, Punch (scale), Shake, SlideIn,
   Fade, CountUp (number), Pulse (loop), Flash (colour), FlyTo (value flies into a table cell).
   Respects a **Reduce motion** setting. Implemented with the Stage 0 tween choice.
3. **`Haptics_Azm` (core, static facade over CandyCoded):** `Tick` (CLOCK_TICK), `Light`,
   `Medium`, `Heavy`, `Confirm`, `Reject`; rate-limited (≥ 40 ms apart) so a fast drag cannot buzz
   continuously; **Haptics on/off** setting; no-op in the Editor.
4. **`UISound_Azm` → `SoundBank_Azm`:** a ScriptableObject of named clips (click, confirm, wrong,
   tick, slide loop, tock, ratchet, chime, whoosh, success) from the CC0 packs, with pitch
   variation and per-clip volume; procedural beeps remain the fallback.
5. **`FeedbackFX_Azm`:** one call = sound + haptic + motion preset, e.g. `FeedbackFX.Correct(rect)`,
   `FeedbackFX.Wrong(field)`, `FeedbackFX.Tap(button)`. Every HUD uses these instead of ad-hoc code.
6. **Button feel for every button:** `ButtonFeel_Azm` (press squash 0.95, release spring, click,
   light haptic; disabled-tap = small shake + reason toast). Added automatically by the builders.
7. **Settings panel:** add Haptics on/off, Reduce motion, Large text.

# STAGE 3 — New HUD layout and interaction design (Cylinder + Screw Gauge first)
1. **Instruction card** (replaces the pill): short action line (≤ 8 words) + a **"Why?"** chip that
   expands the reason; a **segmented step progress bar** under it (one segment per step, ticks
   green with a check animation).
2. **Coach area** (replaces hint-in-toast): hints appear in a fixed zone that never overlaps the
   apparatus or the magnifier, with an icon and a dismiss; messages keep the toast.
3. **Escalating help:** 1st wrong reading → specific hint pointing at a zone of the magnifier
   ("look for the line that meets a main-scale mark exactly"); 2nd → stronger hint; 3rd → offer
   "Show me". Never the answer itself. Counts kept for the results card.
4. **Keypad:** a live reading line `Y = 21 mm + 6 × 0.1 mm = 21.6 mm` that fills as the student
   types; bigger keys; wrong field shakes and is outlined; correct value flies into the table.
5. **Labels for icon-only buttons** (drawer strip and collapsed view buttons): short labels or a
   one-time tooltip.
6. **Colour + text everywhere:** e.g. "✓ within 15°", "zero error: negative" — not colour alone.
7. **Magnifier polish:** bigger numerals, a clear index pointer, lens open/close animation.
8. Test 16:9 and 20:9; touch targets ≥ 120 px; nothing in the bottom 40 px gesture zone.

# STAGE 6 — Juice per practical
**Rule: feedback may follow what the student does, never reveal a reading.** Cues that would give
away an answer (e.g. a buzz when vernier lines coincide) are Learn-mode only or not built.
- **Shared:** correct → line glow + value flies into the table + chime + Confirm haptic; wrong →
  gentle shake + soft sound + Reject haptic; step done → progress segment fills with a check;
  panels ease in/out; results g / A / V / t count up.
- **Pendulum:** thread tension + creak while holding; release snap; tap button ripple + count pop
  + Tick haptic; 20th tap ring burst + stopwatch click; Learn-mode-only faint centre glow as the
  bob passes; graph points drop in one by one, the best-fit line draws itself, g counts up, a
  small theme-coloured celebration when within 2 %.
- **Vernier:** jaw slide sound pitched by drag speed; Tick haptic per 1 mm of travel; "tock" +
  camera nudge when the jaws touch; magnifier zooms open; Learn-mode pulse on the vernier zero at
  the zero-error step; calc lines type in.
- **Screw gauge:** Tick every 5 divisions while turning; ratchet "trrr-click" + 3-pulse haptic +
  wobble; closing with the thimble alone → strip squash + red flash (the caution, felt); lock
  lever click + padlock snap.
- **Menu:** cards float in one after another; a completed card gets a shine sweep; splash logo
  animation (≤ 3 s).
- Performance check on a low-end profile: still 60 fps target, never below 30.
